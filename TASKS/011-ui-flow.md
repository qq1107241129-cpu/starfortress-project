# TASKS/011-ui-flow

## 1. 任务目标

完成 MVP 主流程 UI，使玩家能从主界面进入战斗、查看结算、升级建筑、升级塔、查看星核重构和设置，并适配竖屏。

## 2. 背景说明

MVP 需要一条完整可玩的用户路径。UI 不追求最终美术，但需要清晰、可操作、状态完整，不遮挡核心战斗内容。

## 3. 涉及文件

- `assets/scripts/ui/MainUI.ts`
- `assets/scripts/ui/BattleUI.ts`
- `assets/scripts/ui/SettlementUI.ts`
- `assets/scripts/ui/BuildingUI.ts`
- `assets/scripts/ui/TowerUpgradeUI.ts`
- `assets/scripts/ui/RebirthUI.ts`
- `assets/scripts/ui/SettingsUI.ts`
- `assets/scripts/core/GameManager.ts`
- `docs/GAME_DESIGN.md`
- `docs/ART_GUIDE.md`
- `CHANGELOG.md`

## 4. 允许修改范围

- 新增或更新 MVP UI 脚本和必要的界面流程。
- 创建基础按钮、面板、资源显示和状态提示。
- 接入已有战斗、建筑、塔升级、重构和设置入口。
- 更新 UI 设计文档和变更记录。

## 5. 禁止修改范围

- 不做营销落地页。
- 不做复杂皮肤、商城、排行榜、好友系统。
- 不新增平台广告和分享逻辑。
- 不重写已完成业务系统。
- 不使用侵权或不合规素材。

## 6. 实现假设

- UI 先使用占位资源。
- 所有界面优先适配竖屏。
- 主流程以功能清晰为目标，不追求最终视觉品质。

## 7. 实现步骤

1. 实现主界面入口：开始战斗、建筑、塔升级、星核重构、设置。
2. 实现战斗 UI：倒计时、基地生命、资源提示、主动技能按钮、肉鸽选择入口。
3. 实现结算 UI：胜负、奖励、继续和返回。
4. 实现建筑升级 UI：建筑等级、成本、效果、升级按钮。
5. 实现塔升级 UI：塔等级、成本、属性变化。
6. 实现星核重构 UI：条件、预计星核碎片、永久技能、确认。
7. 实现设置 UI：音效、震动、存档调试预留。
8. 统一竖屏布局与基础视觉样式。
9. 更新文档与 changelog。

## 8. 验收标准

1. 玩家能从主界面进入战斗。
2. 战斗结束能回主界面。
3. 能升级建筑。
4. 能升级塔。
5. 能查看星核重构。
6. UI 适配竖屏。
7. 核心文本和按钮不重叠。

## 9. 测试方式

- Web 预览完整走一遍主界面 -> 战斗 -> 结算 -> 主界面。
- 在窄屏和高屏比例下检查布局。
- 点击所有主要按钮，确认无死路。
- 检查资源不足、可升级、不可升级等状态。

## 10. 回滚方式

- 恢复 UI 脚本和 GameManager 流程变更。
- 恢复文档与 changelog。
- 如创建了临时 UI 资源，删除或恢复。

## 11. 给执行 Agent 的执行提示词

你是《星垒计划》的执行工程师。当前任务是 MVP 主流程 UI。请只实现主界面、战斗 UI、结算 UI、建筑升级、塔升级、星核重构和设置入口。

不要做营销页、商城、排行榜、好友系统、皮肤或平台广告分享。完成后输出完整 Web 预览路径和竖屏适配检查结果。
