# TASKS/009-idle-offline-reward

## 1. 任务目标

实现在线与离线放置收益，包括在线收益计时、离线收益计算、离线收益上限、工厂提升上限和离线结算弹窗。

## 2. 背景说明

放置收益让玩家离开游戏后仍有期待。MVP 中在线收益高于离线收益，离线收益约为在线收益的 30% 到 50%，并有时间上限。

## 3. 涉及文件

- `assets/scripts/base/IdleIncomeManager.ts`
- `assets/scripts/base/BuildingManager.ts`
- `assets/scripts/core/SaveManager.ts`
- `assets/scripts/core/TimeManager.ts`
- `assets/scripts/data/EconomyConfig.ts`
- `assets/scripts/ui/OfflineRewardUI.ts`
- `docs/GAME_DESIGN.md`
- `docs/TECH_DESIGN.md`
- `CHANGELOG.md`

## 4. 允许修改范围

- 新增或更新放置收益管理、时间管理和离线结算 UI。
- 接入建筑等级对收益和上限的影响。
- 更新经济配置、文档和变更记录。

## 5. 禁止修改范围

- 不接真实广告翻倍。
- 不接服务器校时。
- 不实现复杂反作弊。
- 不新增经营资源种类。
- 不接平台 API，除非通过已有 platform storage。

## 6. 实现假设

- Web 调试使用本地时间。
- 离线收益上限初始值可配置。
- 工厂等级提高离线收益上限。
- 广告翻倍只预留入口，不要求真实广告。

## 7. 实现步骤

1. 在经济配置中定义在线收益、离线倍率、初始离线上限和工厂加成。
2. 实现在线收益计时。
3. 在存档中记录 `lastOfflineTimestamp`。
4. 启动时计算离线时长。
5. 应用离线收益上限。
6. 根据建筑等级计算最终收益。
7. 显示离线收益弹窗。
8. 领取后保存资源和新时间戳。
9. 更新文档与 changelog。

## 8. 验收标准

1. 在线能持续产出经营币。
2. 关闭后重新进入能结算离线收益。
3. 离线收益有上限。
4. 工厂升级能提高上限。
5. 收益能保存。
6. 广告不可用不影响领取基础收益。

## 9. 测试方式

- Web 预览运行并观察在线收益增加。
- 手动修改存档时间戳模拟离线。
- 测试超过上限的离线时长。
- 升级工厂后再次测试上限变化。
- 领取离线收益后刷新，确认不会重复领取。

## 10. 回滚方式

- 恢复放置收益、时间管理、存档和 UI 相关改动。
- 恢复经济配置和文档。
- 清理测试存档数据。

你是《星垒计划》的执行工程师。当前任务是在线与离线放置收益。请只实现收益计时、离线计算、上限、工厂加成和离线弹窗。

不要接真实广告、服务器校时、支付或复杂反作弊。完成后输出在线收益、离线收益、上限和工厂加成的验证步骤。
