# TASKS/011.5-battle-visual-demo

## 任务名称

011.5-battle-visual-demo：最小可视化战斗 Demo

## 当前背景

当前项目已完成 `011-ui-flow`，主界面、开始战斗入口、结算 UI、基础流程已经具备。

但当前战斗仍主要停留在逻辑层：

* `EnemySpawner` 只创建逻辑敌人对象，没有创建 Cocos 敌人节点。
* `TowerManager.placeTower()` 只创建逻辑防御塔对象，没有创建塔节点。
* `ProjectileManager` 只维护逻辑投射物数据，没有弹道节点。
* `GameBootstrap` 对敌人生成、死亡、基地受伤等事件主要是 `console.log` 和刷新调试 Label。
* 玩家点击“开始战斗”后，看不到塔、敌人、投射物和攻击反馈。

因此，在进入 `012-build-wechat-douyin-taptap` 平台构建前，需要先补齐一个最小可视化战斗 Demo，让 Web 预览中可以肉眼看到“塔打怪”的基本过程。

## 任务目标

实现一个最小可视化战斗层，不重写现有战斗逻辑，只把已有逻辑对象和事件映射成可见节点。

完成后应达到：

1. Web 预览中可以从主界面点击“开始战斗”进入战斗。
2. Battle 场景中可以看到固定塔位或防御塔占位图。
3. 敌人生成时可以看到敌人节点出现在路径起点。
4. 敌人可以沿路径移动。
5. 塔攻击时可以看到简单投射物或攻击反馈。
6. 敌人死亡后，对应可视节点消失。
7. 战斗倒计时、基地血量、敌人数量、结算 UI 仍正常工作。
8. 不改变现有战斗数值和核心逻辑。
9. 不做平台构建，不进入 012。

## 实现要求

### 1. BattleVisualManager

新增 `BattleVisualManager`，作为战斗可视化入口。

职责：

* 管理塔、敌人、投射物或攻击反馈的显示。
* 监听现有战斗事件，或从现有 Manager 读取只读状态。
* 创建和销毁可视节点。
* 在 `update(deltaTime)` 中同步逻辑对象位置到 Cocos 节点。
* 不持有或修改核心战斗数值。
* 不决定伤害、死亡、波次、结算等逻辑。

建议能力：

```txt
init(...)
reset()
update(deltaTime)
showTower(...)
showEnemy(...)
removeEnemy(...)
showProjectile(...) 或 showAttackEffect(...)
clearAll()
```

### 2. EnemyView

新增 `EnemyView`，用于显示敌人。

最低要求：

* 可以用简单 Sprite、Color Sprite、Label 或占位节点表示敌人。
* 敌人生成时创建节点。
* 敌人移动时更新节点位置。
* 敌人死亡或离场时销毁节点。
* 可以显示简单血条或血量文本，但不是必须。

### 3. TowerView

新增 `TowerView`，用于显示防御塔或固定塔位。

最低要求：

* Battle 场景中能看到至少 4 个固定塔位或防御塔占位图。
* 塔节点位置固定。
* 塔攻击时可以有简单反馈，例如闪烁、缩放、颜色变化或攻击线。
* 不要求正式美术资源。

### 4. ProjectileView / AttackEffectView

可以二选一：

方案 A：最小投射物节点

* 塔攻击时创建一个小圆点或简单节点。
* 从塔位置移动到敌人位置。
* 命中后销毁。

方案 B：最小攻击反馈

* 不创建真实子弹。
* 攻击时显示一条短暂攻击线、闪烁、缩放或命中特效。
* 只要求肉眼能看出“塔在攻击敌人”。

优先选择实现成本低、稳定性高的方案。

### 5. 场景绑定

需要在 Cocos Creator 3.8.x 中完成：

* 在 `Battle.scene` 中创建可视化根节点，例如：

```txt
Canvas
└─ BattleVisualRoot
   ├─ TowerLayer
   ├─ EnemyLayer
   ├─ ProjectileLayer 或 EffectLayer
   └─ PathLayer
```

* 将 `BattleVisualManager` 挂载到合适节点。
* 绑定必要的 Layer 节点。
* 保存 `Battle.scene`。

要求：

* 不手写 `.scene` JSON。
* 新增脚本 `.meta` 必须由 Cocos Creator 自动生成。
* Web 预览前必须确认没有 Missing Script。

## 路径与坐标要求

可以先使用固定路径，不做复杂寻路。

建议最小路径：

```txt
起点：屏幕上方或左侧
中间点：屏幕中部
终点：基地位置
```

示例：

```txt
EnemyPath:
(-250, 350) -> (-100, 150) -> (80, 0) -> (220, -300)
```

具体坐标可根据当前竖屏 Canvas 调整。

要求：

* 敌人移动方向要肉眼可见。
* 敌人最终靠近基地位置。
* 不需要精准地图编辑器。
* 不需要正式路线美术。

## 与现有逻辑的关系

可视化层必须依附现有逻辑，不应成为新的战斗逻辑源。

允许：

* 监听敌人生成、死亡、攻击等事件。
* 读取敌人当前位置、血量、是否存活等只读状态。
* 读取塔位置、攻击目标等只读状态。
* 根据逻辑对象 ID 维护节点映射。

不允许：

* 可视化层重新计算伤害。
* 可视化层决定敌人死亡。
* 可视化层决定塔攻击频率。
* 可视化层修改关卡数值。
* 可视化层替代 `BattleManager.update()`。
