# TASKS/015.4-tower-upgrade-effective-stats-and-detail-panel.md

## 任务目标

1. 修复战斗内放塔读取存档塔等级，使局外升级生效
2. 点击已放置塔显示详情面板，显示当前实际生效属性

## 背景说明

### 问题一：升级属性未生效

- `TowerUpgradeUI.ts` 升级后持久化到 `saveMgr.updateSave({ towerLevels: towerLevelsObj })`
- `BattleUI.ts` 第416行硬编码传入 `level = 1`，没有从存档中读取塔等级
- `TowerController.ts` 构造函数根据 level 获取对应的等级配置

### 问题二：点击塔显示具体属性

- 没有点击已放置塔的事件
- `TowerController` 已有 `getAttack()`、`getAttackSpeed()`、`getRange()` 等方法
- 需要新增 `getEffectiveStats()` 方法返回所有属性

## 实现计划

### 1. 修复战斗内放塔读取存档塔等级

修改 `BattleUI.ts`，从 SaveManager 读取存档中的塔等级：

```typescript
// 修改前：
const success = this._battleManager.placeTower(this._currentSlotId, towerConfig.id, 1);

// 修改后：
const saveMgr = BaseManager.getInstance().getSaveManager();
const save = saveMgr.getSave();
const towerLevel = save.towerLevels?.[towerConfig.id] ?? 1;
const success = this._battleManager.placeTower(this._currentSlotId, towerConfig.id, towerLevel);
```

### 2. 新增事件常量

在 `EventBus.ts` 新增：

```typescript
TOWER_DETAIL_SHOW: 'battle:tower_detail_show',
TOWER_DETAIL_HIDE: 'battle:tower_detail_hide',
```

### 3. 新增 TowerController.getEffectiveStats()

返回当前实际生效属性：

```typescript
getEffectiveStats(): TowerEffectiveStats {
    return {
        id: this._state.id,
        configId: this._state.configId,
        name: this._config.name,
        type: this._config.type,
        level: this._state.level,
        attack: this.getAttack(),
        attackSpeed: this.getAttackSpeed(),
        range: this.getRange(),
        splashRadius: this.getSplashRadius(),
        chainCount: this.getChainCount(),
        slowFactor: this.getSlowFactor(),
        slowDuration: this.getSlowDuration(),
    };
}
```

### 4. 在 BattleVisualManager.ts 处理点击已放置塔

- 监听 `TOUCH_START` 或 `MOUSE_DOWN` 事件
- 检测点击位置是否在已放置塔的范围内
- 如果是，发出 `TOWER_DETAIL_SHOW` 事件
- 避免和空塔位选择冲突

### 5. 在 BattleUI.ts 动态创建详情面板

- 监听 `TOWER_DETAIL_SHOW` 事件
- 动态创建详情面板节点
- 显示塔名称、等级、伤害、攻速、射程、特殊属性
- 带关闭按钮
- 使用 `setSiblingIndex` 置顶

## 验收标准

1. 局外升级某个塔后，进入战斗放置该塔，实际属性使用升级后的等级
2. 战斗中点击已放置塔，弹出塔详情面板
3. 面板显示当前塔等级和实际属性
4. 面板属性和实际攻击表现一致
5. 机枪塔、炮塔、冰塔、电塔都能查看
6. 点击塔不会误触发重新放塔
7. 塔位选择面板、肉鸽选择面板不被塔详情面板破坏
8. 关闭详情面板后战斗正常继续
9. 不修改 `.scene`
10. 不修改 TowerConfig 基础数值

## 测试方式

1. 在 Cocos Creator 中运行 Web 预览
2. 在局外升级机枪塔到 Lv.2
3. 进入战斗放置机枪塔
4. 观察塔的攻击是否比 Lv.1 强
5. 点击已放置的机枪塔，查看详情面板
6. 确认面板显示 Lv.2 和升级后的属性
7. 点击其他类型的塔，确认都能查看
8. 关闭详情面板，确认战斗正常继续
9. 观察控制台是否有报错

## 风险点

1. **SaveManager 初始化时序**：需要确保 BaseManager 和 SaveManager 在 BattleUI 使用前已初始化
2. **点击塔和点击塔位的冲突**：需要区分点击已放置塔和点击空塔位
3. **详情面板和肉鸽面板的冲突**：需要确保详情面板不影响肉鸽面板的置顶逻辑
