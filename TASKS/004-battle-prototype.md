# TASKS/004-battle-prototype

## 1. 任务目标

实现最小塔防战斗原型，使玩家能开始一局、看到敌人沿路径移动、基地受伤，并在 3 分钟或失败时结算奖励。

## 2. 背景说明

战斗原型用于验证核心体验，不要求完整塔系统、复杂敌人波次或最终美术。该任务应尽量使用已有配置系统。

## 3. 涉及文件

- `assets/scripts/battle/BattleManager.ts`
- `assets/scripts/battle/StageManager.ts`
- `assets/scripts/battle/EnemySpawner.ts`
- `assets/scripts/battle/EnemyController.ts`
- `assets/scripts/battle/BattleSettlement.ts`
- `assets/scripts/core/EventBus.ts`
- `assets/scripts/core/TimeManager.ts`
- `assets/scripts/data/StageConfig.ts`
- `docs/GAME_DESIGN.md`
- `CHANGELOG.md`

## 4. 允许修改范围

- 新增或更新最小战斗流程脚本。
- 使用简单占位节点或临时形状表达敌人、路径、基地。
- 增加必要的战斗事件。
- 更新战斗设计文档和变更记录。

## 5. 禁止修改范围

- 不实现完整塔系统。
- 不实现肉鸽选择和主动技能。
- 不实现经营建筑。
- 不接平台 API。
- 不创建超出 MVP 的关卡内容。

## 6. 实现假设

- 战斗时长按 180 秒配置。
- 战斗地图可先使用固定路径点。
- 敌人到达基地时扣基地生命。
- 失败也应给予少量奖励。

## 7. 实现步骤

1. 创建战斗状态：未开始、进行中、胜利、失败、结算。
2. 支持开始指定关卡。
3. 实现 3 分钟倒计时。
4. 实现敌人沿固定路径移动。
5. 实现基地生命值与受伤逻辑。
6. 实现胜利 / 失败判定。
7. 实现结算数据，包含奖励资源、击杀数、关卡结果。
8. 通过事件通知 UI 或后续系统。
9. 更新文档与 changelog。

## 8. 验收标准

1. 能开始一局。
2. 敌人能移动。
3. 敌人到达基地会造成伤害。
4. 3 分钟后能结算。
5. 基地生命归零会失败结算。
6. 结算能给资源数据。

## 9. 测试方式

- Web 预览启动一局，观察敌人沿路径移动。
- 手动缩短关卡时间测试胜利结算。
- 手动降低基地生命测试失败结算。
- 检查结算奖励是否符合配置。

## 10. 回滚方式

- 删除新增战斗原型脚本。
- 恢复相关配置和文档。
- 确认项目回到任务前状态。

## 11. 给执行 Agent 的执行提示词

你是《星垒计划》的执行工程师。当前任务是最小战斗原型。请只实现开始战斗、敌人移动、基地受伤、胜负判定和结算。

不要实现完整塔系统、肉鸽、主动技能、经营建筑或平台功能。所有不确定内容记录到本任务“实现假设”。完成后输出 Web 预览验证方式和三端小游戏影响说明。
