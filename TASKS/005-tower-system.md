# TASKS/005-tower-system

## 1. 任务目标

实现 MVP 四种塔：机枪塔、炮塔、冰塔、电塔，并让塔属性来自配置。

## 2. 背景说明

塔防战斗的核心可玩性来自塔的攻击差异。MVP 只做固定塔位和四种塔，不做自由摆放和更多塔类型。

## 3. 涉及文件

- `assets/scripts/battle/TowerManager.ts`
- `assets/scripts/battle/TowerController.ts`
- `assets/scripts/battle/ProjectileManager.ts`
- `assets/scripts/battle/EnemyController.ts`
- `assets/scripts/data/TowerConfig.ts`
- `assets/scripts/data/EnemyConfig.ts`
- `docs/GAME_DESIGN.md`
- `CHANGELOG.md`

## 4. 允许修改范围

- 新增或更新塔管理、塔控制、投射物和目标选择逻辑。
- 为敌人补充受伤、减速和状态接口。
- 更新塔配置与相关文档。

## 5. 禁止修改范围

- 不实现自由摆放。
- 不新增 MVP 外塔类型。
- 不实现完整塔升级 UI。
- 不实现肉鸽强化。
- 不接平台 API。

## 6. 实现假设

- 塔位固定，可由场景节点或临时配置提供。
- 塔攻击优先选择射程内距离基地最近或路径进度最高的敌人。
- 炮塔范围伤害、冰塔减速、电塔链式攻击先做可验证版本。

## 7. 实现步骤

1. 创建塔基础状态：id、等级、射程、攻击、射速、攻击类型。
2. 实现目标选择。
3. 实现机枪塔单体高频攻击。
4. 实现炮塔范围伤害。
5. 实现冰塔减速效果。
6. 实现电塔链式攻击。
7. 接入敌人受伤与死亡逻辑。
8. 确保塔属性来自 `TowerConfig`。
9. 更新文档与 changelog。

## 8. 验收标准

1. 4 种塔都能攻击。
2. 机枪塔表现为单体高频。
3. 炮塔有范围伤害。
4. 冰塔能减速。
5. 电塔能链式攻击。
6. 塔属性来自配置。

## 9. 测试方式

- Web 预览分别放置或启用四种塔。
- 观察每种塔攻击表现是否不同。
- 使用多敌人场景验证炮塔和电塔。
- 使用高速敌人验证冰塔减速。
- 检查配置修改后塔表现变化。

## 10. 回滚方式

- 删除或恢复塔系统相关脚本。
- 恢复敌人控制器中本任务增加的接口。
- 恢复塔配置和文档。

## 11. 给执行 Agent 的执行提示词

你是《星垒计划》的执行工程师。当前任务是实现 MVP 四种塔。请只做固定塔位下的机枪塔、炮塔、冰塔、电塔攻击逻辑，并保证属性来自配置。

不要实现自由摆放、额外塔类型、肉鸽强化、完整 UI 或平台功能。完成后输出四种塔的 Web 验证方法。
