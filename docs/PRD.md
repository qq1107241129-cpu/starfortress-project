# 《星垒计划》PRD

## 1. 项目定位

《星垒计划 / Starfortress Project》是一款科幻塔防 + 放置 + 经营 + 轻度肉鸽 + 转生养成小游戏。玩家在异星前线建设基地，通过 3 分钟一局的自动塔防抵御机械敌潮，获得资源后升级塔防、基地、建筑与放置系统。后期通过“星核重构”获得“星核碎片”，解锁永久技能、特殊能力、新塔和新建筑。

核心定位：

```txt
披着塔防皮的模拟经营小游戏
```

## 2. 产品目标

### 第一目标

做出一个能玩的核心 Demo，验证“塔防战斗 + 基地经营 + 放置收益 + 转生成长”的闭环是否成立。

### 第二目标

让玩家持续感受到：

1. 打一局有收益。
2. 升级后明显变强。
3. 基地建设有成长感。
4. 放置收益有期待感。
5. 星核重构后有长期目标。

### 第三目标

为微信小游戏、抖音小游戏、TapTap 小游戏发布方向做准备。第一阶段优先落地和验证，不以商业化为最高优先级。

## 3. 目标平台

- 第一阶段：微信小游戏、抖音小游戏、TapTap 小游戏。
- Web 预览：作为开发调试和玩法验证环境。
- 第二阶段可选：TapTap Android APK。

## 4. 用户体验目标

玩家进入游戏后，应在 3 分钟内理解：

1. 我在守一个科幻前线基地。
2. 敌人会沿路线自动进攻。
3. 我的塔会自动攻击。
4. 我可以通过局内肉鸽选择和主动技能提高上限。
5. 一局结束后能获得战斗金币。
6. 战斗金币和经营币可以升级基地、建筑和塔防。
7. 基地会产生在线 / 离线放置收益。
8. 长期游玩可以星核重构，获得星核碎片和永久技能。

## 5. 核心玩法循环

```txt
3 分钟塔防战斗
-> 获得战斗金币
-> 升级塔防、基地、建筑、放置系统
-> 经营和放置产出经营币
-> 经营币反哺塔防成长
-> 达成条件后星核重构
-> 获得星核碎片
-> 解锁永久技能、特殊能力、新塔、新建筑
-> 下一轮更强
```

## 6. 局内塔防玩法

- 每局 3 分钟。
- 自动战斗能发挥约 80% 效果。
- 玩家通过局内 3 选 1 肉鸽强化和主动技能提高上限。
- MVP 固定塔位，不做自由摆放。
- MVP 只做 1 张科幻基地外环地图。
- 最后 30 秒出现精英或小 Boss。
- 失败也给少量奖励，避免纯挫败。

参考方向是轻度肉鸽成长节奏，但不能复刻任何现有游戏的角色、UI、素材、怪物、塔或具体表现。

## 7. 局外经营玩法

玩家经营一个科幻前线基地。

MVP 建筑：

- 基地核心：主等级，影响解锁和星核重构条件。
- 研究所：提升塔防科技和肉鸽强化品质。
- 矿场：产出经营币。
- 能源反应堆：影响主动技能和能量类加成。
- 工厂：提升在线收益、离线收益上限和后续自动化能力。

## 8. 放置收益

- 在线收益高。
- 离线收益低，约为在线收益的 30% 到 50%。
- 离线收益有时间上限。
- 工厂升级可提高离线收益上限。
- 后续广告可用于离线收益翻倍，但 MVP 只预留接口，不强依赖广告。

## 9. 转生系统

- 系统名称：星核重构。
- 代币名称：星核碎片。

MVP 条件方向：

- 基地核心达到 10 级。
- 通关第 10 关。
- 总战力达到指定值。

星核碎片产量参考：

- 历史最高关卡。
- 基地核心等级。
- 总建筑等级。
- 总战斗力。

星核重构后重置：

- 当前关卡进度。
- 普通建筑等级。
- 当前战斗金币。
- 当前经营币。

星核重构后保留：

- 星核碎片。
- 永久技能。
- 历史最高记录。
- 部分解锁内容。

## 10. 资源系统

### 战斗金币

来源：塔防战斗。

用途：

- 升级塔。
- 升级战斗属性。
- 升级部分建筑。

### 经营币

来源：基地建筑、在线放置、离线放置。

用途：

- 升级建筑。
- 提升塔防科技。
- 解锁新系统。

### 星核碎片

来源：星核重构。

用途：

- 永久技能。
- 特殊能力。
- 后续新塔、新建筑和稀有成长路线。

## 11. 关卡系统

MVP 做 10 关：

1. 第 1 关无脑过，建立目标感。
2. 第 3 关开始需要升级。
3. 第 5 关开始需要考虑肉鸽选择。
4. 第 8 关开始需要经营系统支撑。
5. 第 10 关作为第一次星核重构目标。

## 12. 广告与分享预留

MVP 只预留接口，不强依赖广告和分享。

后续可用于：

- 失败后复活。
- 离线收益翻倍。
- 战斗奖励翻倍。
- 免费刷新肉鸽选项。
- 免费获得主动技能次数。
- 分享战斗成绩或基地等级。

广告或分享失败时，核心流程不能崩溃。

## 13. 存档系统

MVP 存档字段：

```txt
playerLevel
currentStage
highestStage
battleCoin
baseCoin
rebirthToken
baseCoreLevel
labLevel
mineLevel
reactorLevel
factoryLevel
towerLevels
permanentSkillLevels
lastOfflineTimestamp
settings
```

Web 调试使用 `localStorage`，小游戏平台使用平台本地存储能力。第一阶段不接服务器。

## 14. MVP 范围

详见 `docs/GAME_DESIGN.md`。PRD 层确认：MVP 的成功标准是能打、能结算、能升级、能放置收益、能完成第一次星核重构，并能朝三端小游戏构建方向验证。

## 15. 后续扩展方向

- 新塔：火焰塔、召唤塔、激光塔。
- 新建筑：居民区、商店。
- 新主动技能。
- 星核重构高级路线。
- 稀有随机事件。
- 广告与分享商业化。
- TapTap Android APK。

## 16. 风险点

- 多平台构建差异导致适配成本增加。
- 主包小于 4MB 对资源管理要求较高。
- AI 占位素材存在版权和风格不统一风险。
- 数值闭环可能需要多轮调优。
- 过早扩展系统会拖慢 MVP。
