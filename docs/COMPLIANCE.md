# 合规与约束

## 1. 原创与 IP

- 不使用现成游戏角色。
- 不复制其他游戏 UI。
- 不模仿具体商业 IP。
- 不使用可能造成品牌混淆的名称、图标、角色或建筑设计。
- AI 生成素材必须作为原创方向，并保留后续替换空间。

## 2. 平台 API 合规

- 业务代码禁止直接调用 `wx`、`tt`、`tap`、`TapSDK`。
- 平台 API 只能出现在 platform 目录。
- 所有平台能力必须通过统一 platform adapter。
- 平台功能失败时必须降级。

## 3. 广告与分享

MVP 只预留广告与分享接口，不强依赖：

- 失败后复活
- 离线收益翻倍
- 战斗奖励翻倍
- 免费刷新肉鸽选项
- 免费获得主动技能次数
- 加速建筑生产

广告不可用时，不得阻塞核心战斗、收益、升级、转生流程。

## 4. 隐私与存储

- 第一阶段不接服务器。
- 第一阶段不接账号系统。
- Web 调试使用 `localStorage`。
- 小游戏平台使用平台本地存储能力。
- 不采集真实身份信息。
- 不上传玩家数据。

## 5. 支付与商业化

- 第一阶段不接支付。
- 第一阶段不做复杂商城。
- 第一阶段不做充值、订阅、抽卡付费或原生支付 SDK。

## 6. 包体与资源

- 主包目标小于 4MB。
- 大资源必须支持分包或远程资源。
- 占位素材命名规范，便于后续替换。

## 7. 审查要求

每次实现任务后必须确认：

1. 是否符合当前任务。
2. 是否越权修改。
3. 是否违反平台 API 约束。
4. 是否影响小游戏构建。
5. 是否影响主包体积。
6. 是否更新 `CHANGELOG.md` 和 `PROJECT_MEMORY.md`。
